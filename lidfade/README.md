# LidFade

맥북 뚜껑을 닫을 때 화면이 페이드되며 사라지고, 열 때 다시 살아나는 효과.

---

## 먼저 짚고 갈 것

**"애플듀오"라는 제품은 확인하지 못했습니다.** 제 지식에 그런 이름의 애플 제품은
없고, 이 환경에서 검증할 방법도 없었습니다. 그래서 "완전히 동일하게"를 제가 기억에
의존해 흉내 내는 방식으로는 만들 수 없습니다. 그건 추측이지 복제가 아닙니다.

대신 **측정해서 맞추는 방식**으로 만들었습니다. 레퍼런스 효과를 영상으로 찍어서
`tools/fit_curve.py`에 넣으면, 프레임별 밝기를 읽어 타이밍 커브를 숫자로 뽑아내고
설정 파일에 바로 넣습니다. 앱은 그 커브를 그대로 재생합니다. 눈대중으로 "비슷하게"가
아니라, 원본의 커브 자체를 복사하는 구조입니다. 이게 "완전히 동일"에 도달하는
유일하게 정직한 경로입니다.

레퍼런스 영상만 확보하시면 나머지는 이미 다 만들어져 있습니다.

# 1. 제작방법

## 1.1 먼저 알아야 할 벽 세 개

이걸 모르고 시작하면 며칠 날립니다.

**벽 1 — 힌지 각도는 읽을 수 없습니다.**
macOS가 외부에 노출하는 건 `AppleClamshellState`, 즉 열림/닫힘 불리언 하나뿐입니다.
홀 센서가 특정 각도에서 한 번 튀는 게 전부고, 30도인지 60도인지는 어디에도 없습니다.
따라서 "뚜껑이 닫히는 정도에 비례해서 페이드"는 불가능합니다. 만들 수 있는 건
**닫힘 신호를 받은 순간 정해진 시간 동안 재생되는 애니메이션**입니다.

**벽 2 — 신호를 받는 순간 이미 화면은 꺼지는 중입니다.**
뚜껑이 닫히면 커널이 즉시 절전에 들어가고 백라이트는 하드웨어가 끕니다. 평범하게
애니메이션을 시작하면 단 한 프레임도 못 보고 끝납니다.

이걸 뚫는 게 이 프로젝트의 핵심입니다. `IORegisterForSystemPower`로 등록하면
`kIOMessageSystemWillSleep`을 받는데, **등록한 모든 클라이언트가
`IOAllowPowerChange`를 호출할 때까지 커널이 절전을 멈추고 기다립니다.** 커널이 주는
유예는 약 30초입니다. 그 안에서 애니메이션을 돌리고, 끝나면 절전을 풀어줍니다.
이 유예 창이 이 효과가 성립하는 유일한 이유입니다.

`PowerMonitor.swift`가 이걸 담당합니다. 애니메이션이 멈춰도 워치독이 무조건 절전을
풀어주도록 되어 있습니다 — 이게 없으면 가방 안에서 맥북이 안 자고 배터리가 녹습니다.

**벽 3 — 오버레이만으로는 검은색이 안 나옵니다.**
검은 창을 아무리 덮어도 패널은 계속 켜져 있어서 끝이 순수한 검정이 아니라 옅은 회색
발광으로 끝납니다. 실제로 "화면이 꺼진다"로 읽히게 하려면 **백라이트를 같은 커브로
같이 내려야** 합니다. `Backlight.swift`가 `DisplayServices`를 런타임에 찾아서
처리합니다. 비공개 프레임워크라 실패하면 조용히 비활성화되고, 앱은 그대로 돕니다.

## 1.2 효과가 실제로 보이는 순간

솔직하게 말씀드리면, 뚜껑을 끝까지 닫은 상태에서는 사용자가 화면을 볼 수 없습니다.
그래서 이 효과의 가치는 이 네 곳에 있습니다.

| 상황 | 보이는가 |
|---|---|
| 뚜껑을 천천히 닫는 중 (센서가 먼저 튐) | 얕은 각도에서 잔상처럼 보임 |
| **뚜껑을 열 때의 페이드인** | **가장 잘 보이고, 체감 품질의 대부분** |
| 애플 메뉴 > 잠자기, 유휴 절전 | 완전히 보임 |
| 화면 녹화, 데모 영상, 제품 소개 | 완전히 보임 |

**열 때의 페이드인이 실질적인 주력 기능입니다.** 판매할 때도 이쪽을 전면에
내세우는 게 맞습니다. 닫을 때만 강조하면 환불 문의가 들어옵니다.

## 1.3 애니메이션 설계

두 가지 스타일이 있습니다.

**Cinematic** — 화면을 캡처해서 정지 이미지로 띄우고, 그 이미지를 블러 + 축소 +
디졸브합니다. 아래에는 검은 레이어가 처음부터 불투명하게 깔려 있습니다. 캡처본이
아래 화면과 픽셀 단위로 같으니 검은 레이어는 보이지 않고, 캡처본이 사라지면서
자연스럽게 검정으로 녹아듭니다. 화면 기록 권한이 필요합니다.

**Classic** — 검은 레이어의 불투명도만 올립니다. 권한이 필요 없고, 권한이 거부되면
자동으로 이쪽으로 떨어집니다.

구현에서 신경 쓴 지점 몇 개:

- **`CAMediaTimingFunction`을 쓰지 않습니다.** 모든 속성이 하나의 `TimingCurve`에서
  뽑은 명시적 키프레임 테이블로 돌아갑니다. 측정한 커브를 근사가 아니라 그대로
  재생하려면 이 방법뿐입니다.
- **블러 앞에 `CIAffineClamp`를 겁니다.** 없으면 Core Image가 이미지 바깥을 투명으로
  보고 가우시안이 그걸 끌어와서, 화면 가장자리가 먼저 어두워집니다. 그 비네팅 하나로
  "아 이거 오버레이구나"가 티납니다.
- **캡처 → 창 생성 → 표시를 한 트랜잭션 안에서** 처리합니다. 캡처본이 자리잡기 전에
  창이 한 프레임이라도 먼저 뜨면 검은 섬광이 보이는데, 그건 효과가 없느니만 못합니다.
- **창은 `CGShieldingWindowLevel()`** 에 놓습니다. 메뉴바와 Dock 위지만 잠금 화면
  아래입니다. 페이드가 인증 UI를 가릴 수 있으면 안 되니까 이게 맞습니다.

## 1.4 "완전히 동일하게" 맞추는 절차 ← 핵심

여기가 요청하신 부분의 답입니다.

### 1단계: 레퍼런스 촬영

- 슬로우모션으로 찍으세요. **240fps 권장, 최소 120fps.** 60fps면 0.4초 애니메이션이
  24프레임이라 커브 모양이 뭉갭니다.
- **전환 앞뒤로 최소 0.5초씩 정지 화면을 남기세요.** 도구가 밝기의 기준선과
  바닥값을 그 구간에서 읽습니다. 이게 없으면 양끝이 잘려서 실제보다 짧고 급하게
  측정됩니다.
- 화면 녹화를 구할 수 있으면 그게 제일 좋습니다. 카메라 노출 자동조정이 개입하지
  않으니까요. 카메라로 찍는다면 **노출과 화이트밸런스를 반드시 수동 고정**하세요.

### 2단계: 측정

```bash
# 화면 영역만 잘라서 분석 (w:h:x:y)
./tools/fit_curve.py reference.mov --crop 1200:750:340:180
```

출력 예시:

```
frames analysed : 386  @ 239.760 fps
transition      : frame 64 to 168 (plateau threshold 0.0041)
tail correction : +3.9% (threshold hid 3.7% of the animation)
duration        : 0.4512 s
closest bezier  : [0.32, 0.0, 0.14, 1.0]  (rmse 0.00218)

 1.0 |                          ##################
 ...
```

`rmse`가 0.02를 넘으면 원본이 3차 베지어로 표현되지 않는 커브라는 뜻입니다.
그때는 베지어를 무시하고 샘플 테이블을 쓰면 됩니다. 도구가 알아서 알려줍니다.

### 3단계: 적용

```bash
./tools/fit_curve.py reference.mov --crop 1200:750:340:180 --apply
```

`~/Library/Application Support/LidFade/config.json`에 121개 샘플 테이블과 측정된
지속시간이 들어갑니다. 앱이 파일 변경을 감시하고 있어서 **재시작 없이 즉시 반영**됩니다.
메뉴바에서 `Preview effect`를 눌러 바로 비교하세요.

### 4단계: 검증 (이게 진짜 "동일한지" 확인하는 단계)

내 효과를 똑같은 조건으로 녹화해서 다시 측정하고, 원본 측정값과 비교합니다.

```bash
./tools/fit_curve.py mine.mov --crop ... --json mine.json
./tools/fit_curve.py reference.mov --crop ... --json ref.json
```

두 JSON의 `lut`을 비교해서 차이가 프레임당 0.01 이하면 육안으로 구분 불가능합니다.
차이가 남으면 대개 원인은 셋 중 하나입니다: 색 공간(백라이트 감광을 맞추는 거라면
`--linear`를 붙이세요), 블러/축소량, 백라이트 램프 on/off 여부.

### 측정 정확도에 대한 솔직한 한계

경계 검출은 신호가 노이즈 바닥을 벗어나야 전환 시작을 인식합니다. 이징이 걸린 커브는
양끝이 점근적으로 붙기 때문에 항상 몇 프레임이 잘리고, 측정 지속시간이 실제보다
조금 짧게 나옵니다. `correct_tail_clipping()`이 이 편향을 절반 정도 되돌리지만
완전히 없애지는 못합니다. 그래서 도구가 높은 프레임레이트를 요구하는 겁니다 —
240fps에서는 남는 오차가 1% 미만이라 체감되지 않습니다.

보정 로직은 합성 커브로 검증되어 있습니다:

```bash
./tools/fit_curve.py --selftest
```

# 2. 적용방법

## 2.1 빌드

Xcode 15 이상(커맨드라인 툴 포함), macOS 13 이상이 필요합니다.

```bash
cd lidfade
./scripts/build-app.sh
```

`.build/bundle/LidFade.app`이 나옵니다. 서명이 필요하면:

```bash
SIGN_ID="Developer ID Application: 이름 (TEAMID)" ./scripts/build-app.sh
```

## 2.2 설치와 권한

1. `LidFade.app`을 `/Applications`로 옮깁니다.
2. 실행하면 메뉴바에 노트북 아이콘이 생깁니다. Dock에는 뜨지 않습니다 (`LSUIElement`).
3. **화면 기록 권한**을 허용합니다. 시스템 설정 > 개인정보 보호 및 보안 > 화면 기록.
   Cinematic 스타일에서 화면을 캡처하기 위해 필요합니다. 거부하면 Classic으로
   자동 전환되고 앱은 정상 동작합니다.
   - 권한 요청은 메뉴바에서 하도록 해뒀습니다. 뚜껑 닫는 시점에 띄우면 이미 어두워지는
     화면 위에 뜨니까요.
4. 메뉴바 > `Open at login`으로 로그인 시 자동 실행을 켭니다.
5. 메뉴바 > `Preview effect`로 전체 사이클을 바로 확인합니다.

## 2.3 설정

메뉴바 > `Reveal config file` 또는 직접 편집:

```
~/Library/Application Support/LidFade/config.json
```

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `true` | 전체 on/off |
| `style` | `cinematic` | `cinematic` 또는 `classic` |
| `trigger` | `lidOnly` | `lidOnly`는 뚜껑 닫을 때만, `anySleep`은 모든 절전 |
| `closeDuration` | `0.42` | 닫힐 때 길이(초) |
| `openDuration` | `0.52` | 열릴 때 길이(초) |
| `blurRadius` | `26` | 최종 블러 반경(pt) |
| `endScale` | `0.965` | 최종 축소 비율 |
| `tintHex` | `"#000000"` | 수렴할 색 |
| `rampBacklight` | `true` | 백라이트 동시 램프 |
| `maxSleepDeferral` | `3.0` | 절전 지연 상한(초). 안전장치 |
| `builtInDisplayOnly` | `true` | 내장 디스플레이에만 적용 |
| `bezier` | `[0.32,0,0.12,1]` | `lut`이 없을 때 쓰는 커브 |
| `lut` | `null` | 측정된 샘플 테이블. 있으면 `bezier`보다 우선 |

값은 저장 즉시 반영됩니다. 잘못된 값은 앱이 안전 범위로 자릅니다.

## 2.4 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 아무 일도 안 일어남 | 외장 모니터 연결 상태로 뚜껑을 닫으면 시스템이 절전하지 않습니다. 정상 동작입니다 |
| 검은 섬광만 보임 | 화면 기록 권한이 없어 Classic으로 떨어진 상태. 권한 허용 후 재시도 |
| 끝이 완전한 검정이 아님 | `rampBacklight`가 꺼져 있거나 `DisplayServices` 심볼을 못 찾은 경우. `Console.app`에서 `LidFade` 검색 |
| 절전이 느려진 느낌 | 의도된 동작입니다. `closeDuration`만큼 지연됩니다. `maxSleepDeferral`이 상한 |
| 깨어났는데 화면이 검음 | 있어서는 안 되는 버그입니다. `NSWorkspace.didWakeNotification` 이중 안전장치가 걸려 있습니다. 재현되면 Console 로그와 함께 리포트 |

## 2.5 제거

메뉴바 > `Open at login` 해제 후 종료, `/Applications`에서 앱 삭제,
`~/Library/Application Support/LidFade` 삭제.

# 3. 판매방법

> 아래는 실무 안내이지 법률 자문이 아닙니다. 계약, 세무, 상표는 반드시
> 해당 분야 전문가에게 확인하세요.

## 3.1 가장 먼저 — 맥 앱스토어는 불가능합니다

설계상 막혀 있습니다. 우회 방법도 없습니다.

| 필요한 기능 | 앱스토어에서 |
|---|---|
| `IORegisterForSystemPower` 절전 지연 | 샌드박스에서 차단 |
| 전체 화면 캡처 | 샌드박스에서 차단 |
| `CGShieldingWindowLevel()` 오버레이 | 심사에서 거부 |
| `DisplayServices` 백라이트 제어 | 비공개 API, 자동 거부 |

따라서 **직접 배포(Developer ID + 공증)가 유일한 경로**입니다. 이건 단점만 있는 게
아닙니다. 수수료 30%가 없고, 가격과 환불 정책을 직접 정하고, 업데이트가 심사를
안 거칩니다.

## 3.2 배포 준비

**Apple Developer Program 연 $99가 필수입니다.** 서명 없이 배포하면 Gatekeeper가
막고, 사용자가 우클릭-열기 같은 걸 하게 만드는 순간 환불률이 치솟습니다.

```bash
# 최초 1회, 앱 암호는 appleid.apple.com에서 발급
xcrun notarytool store-credentials lidfade-notary \
  --apple-id you@example.com --team-id TEAMID --password xxxx-xxxx-xxxx-xxxx

# 매 릴리스
SIGN_ID="Developer ID Application: 이름 (TEAMID)" ./scripts/build-app.sh
SIGN_ID="Developer ID Application: 이름 (TEAMID)" ./scripts/notarize.sh
```

`notarize.sh`가 DMG 생성, 서명, 공증, 스테이플, Gatekeeper 검증까지 합니다.
**스테이플을 빼먹지 마세요** — 오프라인 사용자에게서 실행이 막힙니다.

업데이트 배포는 [Sparkle](https://sparkle-project.org) 2.x를 붙이세요. EdDSA 서명
appcast 방식이고, 직접 배포 맥앱의 사실상 표준입니다.

## 3.3 결제 플랫폼

| 선택지 | 수수료 | 부가세/세금계산서 | 비고 |
|---|---|---|---|
| **Paddle** | ~5% + $0.50 | 대행(MoR) | 라이선스 키 기능 내장. 1인 개발 추천 |

플랫폼이 대신 처리합니다. 개인 개발자가 이걸 직접 감당하는 건 비현실적입니다.

## 3.4 라이선스 키

Paddle이나 Lemon Squeezy의 내장 라이선스 API를 쓰는 게 가장 빠릅니다. 직접 만든다면
**오프라인 검증이 가능한 Ed25519 서명 방식**으로 하세요:

- 서버가 `{이메일, 제품, 만료일}`을 Ed25519 개인키로 서명해서 키로 발급
- 앱에는 공개키만 박아두고 로컬에서 검증
- 네트워크 없이 동작하고, 서버가 죽어도 기존 사용자가 멀쩡합니다

크랙은 어차피 뚫립니다. **정직한 사용자가 불편하지 않게** 만드는 게 목표지
복사 방지가 목표가 아닙니다. 기기 수 제한은 3~5대로 넉넉히 두세요.

## 3.6 상표와 법적 주의 — 여기는 꼭 읽으세요

**절대 하면 안 되는 것:**

- 제품명에 `Apple`, `MacBook`, 그 밖의 애플 상표를 넣는 것
- 애플 로고, 애플 제품 렌더링, 애플 UI 스크린샷을 마케팅에 쓰는 것
- 특정 애플 제품의 효과를 복제한다고 광고하는 것 ("○○ 효과 그대로!")
- 애플이 만들었거나 인정했다는 인상을 주는 표현

**해도 되는 것:**

- `"Works with Mac"`, `"for macOS"` 같은 **지시적 사용(nominative use)**
- 기능 자체를 서술: "뚜껑을 닫고 열 때 화면이 부드럽게 페이드됩니다"
- 내가 만든 앱 화면을 직접 찍은 스크린샷

**페이드 애니메이션 자체는 보호 대상이 아닙니다.** 단순한 시각 효과에는 저작권이
붙지 않습니다. 문제가 되는 건 **다른 제품의 이름을 빌려 파는 것**입니다. 효과를
똑같이 만드는 건 괜찮고, "○○와 똑같은 효과"라고 광고하는 건 위험합니다.
기능으로 설명하고 팔면 됩니다.

제품명은 애플 상표가 없는 쪽으로 가세요. `LidFade`도 그래서 이 이름입니다.

**국내 판매 시:**

- 사업자등록 + **통신판매업 신고**(관할 구청)
- 전자상거래법상 디지털 콘텐츠는 원칙적으로 **7일 청약철회**. 다만 "다운로드 즉시
  철회 불가"를 고지하고 동의받으면 제한 가능합니다. 체험판을 주는 게 분쟁 예방에
  훨씬 낫습니다
- 해외 플랫폼(Paddle 등) 수익도 종합소득세 신고 대상입니다
