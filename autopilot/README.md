# autopilot — 자는 동안 도는 콘텐츠 파이프라인

패션 콘텐츠를 새벽에 자동 생성하고, 토스쇼핑 쉐어링크 딜을 글로 바꾸는 장치.

플레이리스트(음원) 트랙은 접었다. 커밋 `de0b049` 히스토리에 남아 있다.

## 왜 이렇게 나눠져 있나

생성과 게시는 Higgsfield MCP 도구로만 되고, 그건 **예약 세션의 Claude**가 호출한다.
스크립트가 직접 못 부른다. 반대로 "무엇을 만들지 정하는 일"은 결정론적이라 코드가
맡는 게 싸고 재현된다. 그래서 이렇게 갈랐다.

| 코드가 하는 일 | 세션이 하는 일 |
|---|---|
| 컨셉 선택, 중복 배제 | 이미지/영상 생성 (MCP) |
| 프롬프트·캡션 조립 | 틱톡 게시 (MCP) |
| 음원 API 호출, 2시간 스티칭 | 트렌드 슬롯 갱신 (웹 검색) |

`cli.py` 가 **작업 지시서(brief JSON)** 를 뱉고, 세션은 `runbook/nightly.md` 대로
그 지시서를 실행한다.

## 비용이 구조를 정했다

측정값(2026-09 기준):

| 대상 | 단가 |
|---|---|
| 이미지 `soul_2` 2k | **0.12** 크레딧 |
| 영상 `veo3_1_lite` 8초 | **8** 크레딧 |
| 영상 `kling3_0_turbo` 5초 | 7.5 크레딧 |
| 영상 `seedance_2_5` 5초 | 32.5 크레딧 |

영상이 이미지보다 **약 65배** 비싸다. 그래서 기본 구성은 이미지 6장 + 영상 3개
(약 25 크레딧/일)이고, 잔량이 모자라면 런북이 영상부터 끈다. 인스타 캐러셀이
비용 대비 가장 유리한 포맷인 이유도 이것이다.

## 구성

```
config/     캐릭터·제휴·플랫폼·음악API 설정 (코드 수정 없이 여기만 바꾼다)
core/       중복 배제 상태 관리
fashion/    컨셉 뱅크 3,456조합 / 프롬프트 / 캡션
toss/       쉐어링크 딜 -> 쓰레드/오픈채팅 글 생성
runbook/    새벽 세션이 따라갈 절차
out/        생성물과 state.json (커밋해야 중복 배제가 유지된다)
```

## 시작하기

```bash
pip install -r requirements.txt
python3 cli.py both        # 오늘치 지시서 생성
```

## 아직 안 꽂힌 것

| 항목 | 상태 | 필요한 것 |
|---|---|---|
| 쿠팡 파트너스 | 미가입 | 가입 후 `config/affiliate.json` 에 키 |
| 유튜브 쇼핑 제휴 | 미연동 | 채널 자격 + YouTube Data API OAuth |
| 인스타그램 | 미연동 | 비즈니스 계정 + Graph API 토큰 |
| 토스 쉐어링크 | 발급됨(타인 명의) | 본인 명의 발급 권장 · 운영정책 확인 필요 |
| 쓰레드 자동 게시 | 미연동 | Threads API (비즈니스 앱 + 심사) |
| 카톡 오픈채팅 | 자동화 불가 | 공식 API 없음. 방장봇 + 수동 게시 |

링크 자리는 이미 비워 둬서, 키만 넣으면 캡션에 자동으로 들어간다.

## 지켜야 할 선

- 쿠팡/지그재그 **상품 사진을 캐릭터에 합성하지 않는다.** 판매자 저작물이고
  파트너스 제공 이미지는 비변형 사용이 원칙이다. 착용 컷은 AI 스타일링
  레퍼런스로 따로 만들고, 상품 사진은 원본 그대로 별도 컷으로 쓴다.
- 제휴 링크가 하나라도 있으면 공정위 고지 문구가 캡션 최상단에 붙는다.
  `captions.build()` 가 구조적으로 강제하므로 빼먹을 수 없다.
- AI 생성 이미지임을 함께 고지한다.
