# 새벽 자동 실행 런북

예약 세션(Routine)이 이 문서를 그대로 따라 실행한다. 사람이 깨어 있을 필요가
없도록 판단 지점마다 기본값을 정해 두었다.

> 이 문서는 루틴이 "정본"으로 삼는다. **코드를 바꿨으면 여기도 같이 고친다.**
> 실제로 플레이리스트 모듈을 걷어내고 이 문서를 안 고쳤다가, 루틴이 없는 인자로
> `cli.py` 를 불러 조용히 실패한 적이 있다.

## 0. 준비 확인

```bash
cd autopilot && pip install -q -r requirements.txt
```

크레딧 잔량을 먼저 본다(`balance`). **20 크레딧 미만이면 이미지 생성도 건너뛰고
지시서만 남긴다.** 잔량을 다 태우고 멈추는 것보다 매일 조금씩 나가는 편이 낫다.

## 1. 작업 지시서 생성

```bash
python3 cli.py
```

인자 없이 실행한다. `out/<날짜>-fashion.brief.json` 이 나온다. 컨셉은 이미 쓴
것을 배제하고 뽑히므로 중복 걱정은 하지 않아도 된다.

## 2. 트렌드 슬롯 갱신 (주 1회, 월요일에만)

`fashion/concepts.py` 의 `TREND_ITEMS` 는 손으로 박아 둔 값이라 시간이 지나면
낡는다. 월요일 실행분에서만 웹 검색으로 "이번 주 패션 트렌드 아이템"을 확인하고,
바뀐 게 있으면 리스트를 갱신한 뒤 커밋한다. 다른 요일에는 건드리지 않는다.

## 3. 이미지 생성

1. brief 의 `generate.images.prompts` 를 `generate_image_batch` 로 한 번에 제출한다
   (모델 `soul_2`, `aspect_ratio: 9:16`). 약 0.7 크레딧.
2. `jobs_wait` 로 전부 끝날 때까지 기다린다.
3. 결과를 `show_generation_by_ids` 로 한 번에 정리하고, 이미지 URL을 brief JSON 에
   `results` 키로 덧붙인다.

**영상은 만들지 않는다.** 이미지가 0.12 크레딧인데 영상은 8 크레딧이라 약 65배다.
잔량 192로 매일 릴스를 돌리면 8일이면 바닥난다. 영상이 필요하면 사람이 판단해서
따로 돌린다. 그때는 생성한 이미지를 `start_image` 로 넘겨야 인물이 유지된다
(`prompts.build_video_prompts(concept, job_ids, n)`).

## 4. 게시는 이 세션이 하지 않는다

쓰레드 게시는 GitHub Actions(`.github/workflows/post-to-threads.yml`)가 맡는다.
이 개발 환경은 `graph.threads.net` 이 막혀 있어 애초에 호출이 안 된다.

글을 올리려면 대기열에 넣기만 하면 된다:

```python
from toss.postqueue import enqueue
enqueue(text, link)   # out/queue/ 에 쌓이고 Actions 가 하루 3회 집어간다
```

## 5. 마무리

- `out/` 전체(특히 `state.json`)를 커밋하고 푸시한다.
  상태 파일이 커밋돼야 다음 실행이 중복을 피한다.
- 커밋할 변경이 없으면 푸시하지 않는다.
- **명령이 0이 아닌 종료코드로 끝나면 성공으로 넘기지 않는다.** 에러 전문을 보고에
  담는다. 코드와 이 문서가 어긋난 것으로 보이면 PR 에 한 번 남긴다.

## 하지 말 것

- 토스/쿠팡의 **상품 사진을 받아다 캐릭터에 합성하지 않는다.** 판매자 저작물이다.
  상품 사진은 원본 그대로 별도 컷으로 쓰고, 착용 이미지는 AI로 따로 만든 스타일링
  레퍼런스로 둔다.
- 캡션과 글에서 광고 표시 문구를 빼지 않는다. `captions.build()` 와 `toss.posts`
  가 자동으로 넣는다.
- 같은 컨셉을 이틀 연속 올리지 않는다. `state.json` 이 막아 주지만 수동 실행 시 주의.
- 대기열에 한 번에 많이 쌓지 않는다. Actions 가 회차당 5건까지만 올린다.
